Special Characters in a URL Query Value

Of the nine characters that cause trouble in a query value, only three actually break when written raw: & splits the parameter, + becomes a space, and a newline is deleted or rewritten. The other six — comma, semicolon, colon, equals, question mark, percent — happen to survive in today's parsers, but that is luck, not a rule. Encode the value and all nine decode back exactly. This page is the map; each character has its own measured lab linked below.

Three break, six only appear safe
The useful question is not "is this character reserved?" — it is what does the parser do with the raw byte? Measured in Node.js v22.22.2 and PHP 8.5.12 with the value a<char>b written directly into ?q=:

One rule, not nine exceptions
The six "survivors" are not safe — they are untested against the next parser, framework, or application policy. A comma becomes three values the moment an application splits on it. A semicolon was a parameter separator in earlier CGI conventions. A bare percent stays literal only until the next two characters happen to form a valid hex escape. Encode the value once with URLSearchParams.set(), encodeURIComponent(), or PHP rawurlencode(), and stop classifying characters by hand.

FAQ
Is it safe to leave a comma or colon unencoded?
In today's mainstream parsers, yes — they come back as the same string. But "survives my parser" is not "is data-safe": the meaning can be reassigned by your framework or application (comma lists, semicolon separators). Encoding removes that ambiguity at no cost.
Why does + become a space but %2B stay a plus?
Query values use form-style decoding by default, where a literal + means byte 20 (space). %2B is an explicit escape for byte 2B, the plus character, so it decodes to a real plus. Use encodeURIComponent() or rawurlencode() and this is handled for you.
Do I need to encode all nine every time?
Don't decide character by character. Pass the whole value through an encoder once. The nine labs exist to explain what goes wrong when you don't, not to give you a list to memorize.
