Encode a Percent Sign in a URL Query Value

A percent sign inside a query value is data; the escape prefix is a separate role that only applies to the two hex digits after it. Encode a literal percent as %25 so a receiver cannot mistake it for the start of another escape.

Escape prefix or literal data
Wire formURLSearchParams resultMeaning
q=100%100%A trailing percent with no hex digits is read as literal text by URLSearchParams.
q=100%25100%The percent is explicit data; one decoding step returns the literal character.
q=100%2520100%20One layer was already encoded. The text %20 is data, not a space.
q=100%20sure100 sureHere %20 is an actual escape for a space.

Common failure
Do not re-encode an already escaped value just because it still contains percent signs. Decide first whether each % is an escape prefix or the data character itself; encoding a literal percent twice produces %2525, which decodes back to %25, not %.
FAQ
Why is a literal percent encoded as %25?
Percent-encoding represents a byte as % followed by two hex digits. A bare percent cannot be sent unambiguously as itself, so its UTF-8 byte 0x25 is written as %25.
Does every percent sign start an escape?
No. Only a percent followed by two hex digits forms an escape. A stray percent may be tolerated by a lenient parser, but a strict decoder such as decodeURIComponent throws on it.
