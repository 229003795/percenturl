URL Encoder Online: Encode the Right Part of a URL

A quick, practical way to turn text into URL-safe data without changing the structure of the link around it.

Quick answer: Paste the value you need to put into a URL, encode that value, then insert it into the correct place. In most cases you should encode a query parameter’s value, not the complete URL. Keep separators such as /, ?, =, and & where they belong.

How to use an online URL encoder

  1. Identify the exact text that will become a URL value or path segment.
  2. Paste only that text into the encoder.
  3. Encode it, then copy the result.
  4. Insert the result into the intended part of your URL.
  5. Review the finished link to make sure its separators remain in the right places.

Encoding changes how text is represented; it does not validate that the completed URL points to the right page or that the receiving service accepts the value. Keep the original value until you have checked the link.

Keep URL structure separate from data

A URL contains structural marks as well as values. The same character can serve different jobs: & may separate query parameters or be part of a search phrase; / may divide path segments or be data inside one value. Decide what each character means in context before encoding it.

Suppose the search phrase is red shoes & socks. Encode that phrase, then add it after q=. Keep the real ampersand before sort as a separator:

https://example.com/search?q=red%20shoes%20%26%20socks&sort=price

If you put the raw ampersand inside the value, a query parser can treat the text after it as another parameter. Encoding the value keeps the phrase together.

Check for double encoding

If already encoded text is encoded again, percent escapes become ordinary encoded text. For example, %20 can become %2520 because the percent sign itself becomes %25. The receiving page may then display the escape characters instead of interpreting them as a space.

Before encoding, check whether the input already contains escapes such as %20 or %2F. Confirm whether those sequences are intended encoded data or literal text, then encode once when inserting the raw value into its URL component.

Spaces in a URL and form data

A space may appear as %20 in percent-encoded URLs. In form-style query serialization, it may appear as +; a literal plus in that convention is commonly written %2B. Follow the format expected by the server or API that receives the URL.

For a detailed comparison of component, full-URL, and form modes, see URL encode and decode: choose the right mode.

Before you copy the finished link

  • Did you encode only the value or component you intended?
  • Are /, ?, =, and & still in the right structural positions?
  • Did a literal percent sign become %25?
  • Did you avoid encoding the same value twice?
  • Does the receiving service expect %20 or form-style + for spaces?
