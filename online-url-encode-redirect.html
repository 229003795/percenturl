Online URL Encode: Put a Redirect URL in a Query Parameter

When one URL has to travel inside another URL, encode the inner link as a single value. Keep each layer intact and let the matching URL parser read it back.

Quick answer: Build the inner URL first, then add it as the outer URL’s redirect_uri or next parameter. Encode the inner URL as one parameter value; do not encode the outer URL’s separators. Open the online URL encoder

Why a redirect URL needs two encoding steps

A redirect link often contains another complete URL as a query value. The inner URL has its own ?, &, and = characters. If those characters are pasted raw into the outer query, the outer parser may mistake them for its own separators.

For example, this is ambiguous because the inner &sort=recent can be read as a second outer parameter:

https://login.example/authorize?client_id=abc&redirect_uri=https://shop.example/search?q=tea&sort=recent

Encode the complete inner URL as the value of redirect_uri, while leaving the outer ? and & separators readable:

https://login.example/authorize?client_id=abc&redirect_uri=https%3A%2F%2Fshop.example%2Fsearch%3Fq%3Dtea%26sort%3Drecent

Now the outer URL has two parameters: client_id and redirect_uri. The encoded %26 belongs to the inner link; the literal outer & separates outer parameters.

Encode the inner link in the right order

  1. Build the inner URL with its own parameters.
  2. Serialize the inner URL to text.
  3. Add that string to the outer URL with URLSearchParams or a component encoder.
  4. Read the outer parameter first; parse its returned value as the inner URL.
const inner = new URL("https://shop.example/search");
inner.searchParams.set("q", "tea & cake");
inner.searchParams.set("sort", "recent");

const outer = new URL("https://login.example/authorize");
outer.searchParams.set("client_id", "abc");
outer.searchParams.set("redirect_uri", inner.href);

console.log(outer.href);

URLSearchParams serializes the outer parameter value for you. Spaces in its form-style query serialization may appear as +; an encoder for a generic URL component commonly uses %20. Use the convention expected by the receiving endpoint.

Decode one layer at a time

Parse the outer URL to get redirect_uri, then parse that value as a URL to read the inner search parameters:

const receivedOuter = new URL(outer.href);
const redirectText = receivedOuter.searchParams.get("redirect_uri");
const receivedInner = new URL(redirectText);

console.log(receivedInner.searchParams.get("q")); // "tea & cake"
console.log(receivedInner.searchParams.get("sort")); // "recent"

Each parser handles its own URL boundary. Avoid decoding the complete outer URL before parsing it: turning encoded inner separators into literal characters too early can change which parameters the outer URL appears to contain.

Using an online URL encode tool

If you are encoding by hand, select only the complete inner URL and use a mode intended for a URL component or parameter value. Keep the outer URL’s structure outside the selection. For a long link, inspect the result and confirm that the inner ?, &, and = became encoded while the outer separators remain literal.

Quick checks before using the link

  • Does the outer URL contain exactly one redirect_uri parameter?
  • Does the value decode once into the intended inner URL?
  • Do the inner URL’s own parameters still parse correctly?
  • Does the destination allow that redirect host? Encoding is not an access-control check.
