Plus sign in a URL path vs query: the same +, two meanings

A literal + in a path stays a plus. The same + in a query becomes a space under form-style decoding. /c+guide names a path containing c+guide, but ?x=c+d is read as x=c d by Node's URLSearchParams and PHP's parse_str.

The byte did not change — the component did. Path and query are decoded under different contracts, so one decoder cannot be used for both. This page measures the split in Node.js and PHP and shows which encoder belongs in which component.

The decoder trap

Node's URL.pathname keeps percent escapes as written — /c%2Bguide stays /c%2Bguide. Call decodeURIComponent() on the path segment to get c+guide. The query is different: searchParams.get() already decodes, including the form rule that turns a raw + into a space. Two components, two decoding steps.

PHP exposes the split directly. On c+guide, rawurldecode() returns c+guide (correct for a path), while urldecode() returns c guide — it applies the form rule to a path and silently eats the plus. On c%2Bguide both return c+guide. Use rawurldecode() for paths and parse_str() or urldecode() for form-style query values.

JavaScript's encodeURI keeps + because a plus is legal in a path. PHP's urlencode is a form encoder: it writes a space as +. They are not interchangeable even when both are called "URL encoding".

Common failure

Decoding a whole URL with one function. If you run a form decoder over the path, every literal plus becomes a space and the route no longer matches. Split the URL into components first, then apply the component's contract: path → literal plus; query value → form space unless written as %2B.

Questions people ask

Is a plus always a space in a URL?

No. Only in the query when a form-style decoder is used. In the path a plus is a literal character.

How do I force a literal plus in a query value?

Write it as %2B. Both Node and PHP then decode it back to + instead of a space.

Why does encodeURI keep + but encodeURIComponent does not?

encodeURI is for a whole structured URL and leaves structural characters alone; encodeURIComponent encodes one value where + must not be read as form-space.
