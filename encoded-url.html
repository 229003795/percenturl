Encoded URL: Meaning, Examples, and How to Decode It

An encoded URL uses percent escapes to represent data inside URL components. Learn how to read those escapes without changing the link's structure.

Quick answer: In a percent-encoded URL, a sequence such as %20 represents a byte written with two hexadecimal digits. Decode the component you need after parsing the URL; do not blindly decode the complete URL or repeatedly decode nested values. Open the URL Encode / Decode tool

What does “encoded URL” mean?

People use “encoded URL” to mean a URL that contains percent-encoded characters. A percent escape has the form %HH, where HH is a pair of hexadecimal digits representing one byte. For example, %20 is the byte value 0x20, commonly used for a space in a URL component.

That does not mean every character in the entire link has been replaced. A URL has parts—such as its scheme, host, path, query, and fragment—and visible characters like ?, =, and & often separate those parts. Percent encoding applies to data in a component; those structural separators usually need to remain recognizable.

Read the percent escapes as bytes

For non-ASCII text, a character may become several UTF-8 bytes, and each byte gets its own percent escape. The check mark ✓, for example, is UTF-8 bytes E2 9C 93, so its percent-encoded form is %E2%9C%93. Three escapes here represent one Unicode character.

The percent escapes alone do not tell you every detail of the original input. The decoder also needs the correct character encoding and the right component boundary. Percent encoding is a representation, not encryption: anyone with the URL can decode it.

Example: encoded data inside a query

Suppose a search phrase is tea & cake, and sort is a separate query parameter. Encode the phrase as one value, then assemble the URL:

Value

tea & cake

Encoded value

tea%20%26%20cake

URL with a separate sort parameter

https://example.com/search?q=tea%20%26%20cake&sort=recent

The %26 belongs to the search phrase. The final literal & separates q from sort. Decoding the entire query string before parsing could turn the phrase's encoded ampersand into something that looks like another separator.

Spaces and plus signs are context-dependent

A space in a generic URL component is commonly written as %20. In application/x-www-form-urlencoded query data, a space is serialized as +; in that same form convention, a literal plus is represented as %2B. A plus sign in another URL component, such as a path, is not automatically a space. Check how the URL was produced and how the recipient parses it.

Decode nested URLs one layer at a time

Consider a redirect URL whose next parameter contains another URL. The outer query has to encode characters that belong to the inner link. When the outer query is parsed, its parameter value becomes the inner URL; then parse that inner URL to read its own query:

https://example.com/redirect?next=https%3A%2F%2Fshop.example%2Fsearch%3Fq%3Dtea%2520cake

Parsing next yields:

https://shop.example/search?q=tea%20cake

Parsing the inner query value q then yields tea cake.

In JavaScript, use the URL parser for each layer instead of manually decoding the full string repeatedly:

const outer = new URL("https://example.com/redirect?next=https%3A%2F%2Fshop.example%2Fsearch%3Fq%3Dtea%2520cake");
const innerText = outer.searchParams.get("next");
const inner = new URL(innerText);
const query = inner.searchParams.get("q"); // "tea cake"

Here the outer query parser removes one encoding layer to recover the inner URL. The inner query parser then reads its q value. Each parser handles the structure for its own URL.

Why does %2520 appear?

%25 represents a percent sign. So %2520 decodes once to the three characters %20. That can be correct when an encoded value is intentionally carried inside another encoded component, as in the nested example. In a plain search value, it can also be a sign that already-encoded text was encoded again. Decide what each layer represents before decoding; do not apply repeated decoding just to make escapes disappear.

Use an online decoder carefully

For a whole link, choose a tool mode intended for a complete URL and preserve its separators. For one parameter value, select only that value and decode it once. If the content is a nested URL, parse the outer query first and the inner URL second. These steps help keep data characters from turning into URL syntax.
