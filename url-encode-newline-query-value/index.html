Encode a Newline in a URL Query Value

A line break inside a query value is data, but a literal newline on the wire is not preserved — parsers delete or rewrite it before you ever read the value. Encode LF as %0A and CRLF as %0D%0A so the character survives parsing and decodes back exactly.

Common failure
Putting a real line break into a URL — by pasting multi-line text into a query builder, or by interpolating a textarea value without encoding — does not send a newline. It sends a raw control byte that the receiving parser strips or rewrites, so the two lines merge (Node) or gain underscores (PHP). Encode the value first: use URLSearchParams.set(), encodeURIComponent(), or PHP rawurlencode(). ASCII tab (0x09) and carriage return (0x0D) have the same problem and should be encoded as %09 and %0D.
FAQ
Why does my newline disappear from the query value?
Because a bare LF/CR is a control character, not a legal query-value byte on the wire. Node's URL parser removes tab, LF and CR before parsing; PHP's parse_url converts them to underscores. Neither returns your original two-line value. Encoding as %0A avoids both paths.
Is %0A a space? Is it the same as +?
No. %0A is byte 0A, a line feed. A space is byte 20, written %20 or, in form-style query values, +. They are three different characters and do not decode to each other.
