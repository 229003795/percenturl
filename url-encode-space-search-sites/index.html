URL Encode Space: Six Search Sites Compared

A dated field check of how six site search boxes represent spaces in their query URLs.

Short answer: On October 6, 2026, six tested search boxes wrote spaces as + in their query parameters. YouTube also normalized a tested %20 query to +; the result is specific to these endpoints and this input.

On October 6, 2026, YouTube displayed the same search phrase, url encode space, for search_query=url%20encode%20space and search_query=url+encode+space, then normalized the %20 address to +.

All six site searches—Google, YouTube, Wikipedia, Amazon, GitHub, and eBay—serialized spaces as + in their query parameters on October 6, 2026. This is a dated six-site sample, not an internet-wide count.

That is what these specific search endpoints did during this check. It is not a rule for every URL, path, API, or website.

Did %20 and + show different searches?

We opened each endpoint with the same words, changing only the two spaces:

For this input on these endpoints, either spelling reached the same visible search words. The address-bar behavior was not identical: YouTube normalized %20, while Google and Wikipedia retained the submitted spelling.

What this check shows—and what it does not

  • In this sample, a visible + in each site's search query corresponded to a space in the phrase displayed by the site.
  • This does not show that + means a space in every URL component. It covers only the named search query parameters and tested input.
  • When building a link for another service, follow that service's expected query format and verify the resulting value. A literal plus sign and a space are different input characters.

How we checked

On October 6, 2026, we entered the exact phrase url encode space into each of the six sites' own search fields and recorded the resulting URL. For the paired check, we opened the same Google, YouTube, and Wikipedia search endpoints twice, once using %20 and once using +, then compared the final address and visible query text.

Reddit required login or a developer token before a search could be submitted, and Stack Overflow showed an anti-bot challenge, so neither was counted.
