Encode Basic Auth Credentials in a URL Safely

Encode reserved characters inside the username or password, but do not treat URL userinfo as a secure storage mechanism. An unescaped @ can terminate credentials early and change which host the parser sees.

Common failure
Do not put real passwords or API keys in shareable URLs. Encoding prevents delimiter collisions; it does not encrypt the credential, and URLs may appear in browser history, logs, referrers, and screenshots.
FAQ
Should I encode the whole URL?
No. Encode the username and password components before building the authority, then leave the host, port, path, and query delimiters structural.
Can the browser send this securely?
Use HTTPS and prefer an authentication mechanism that does not expose secrets in URLs. URL parsing success is not a security approval.
