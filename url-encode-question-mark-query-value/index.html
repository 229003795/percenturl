Encode a Question Mark in a URL Query Value

The first question mark starts the query; a question mark inside a value is data and should be encoded as %3F. Keeping those two roles separate prevents a value from being mistaken for a second query boundary.

Common failure
Do not split an entire URL on every question mark. Parse the first boundary, then encode question marks that belong to a component value.
FAQ
Is a second question mark always a new query?
No. The first one establishes the query; later question marks are normally part of the value, although application-specific parsers can impose different rules.
Does encoding the question mark change the decoded value?
No. It makes the component boundary unambiguous on the wire; decoding returns the original character.
